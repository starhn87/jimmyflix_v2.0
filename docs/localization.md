# 한국어·영어 전환

Jimmyflix는 App Router의 최상위 동적 세그먼트로 언어를 구분한다. 지원 언어는 영어 `en`과 한국어 `ko`다.

## URL과 언어 선택

- 모든 화면은 `/{locale}` 아래에 있다. 예: `/en`, `/ko/tv`, `/ko/movies/123`.
- 언어가 없는 기존 주소로 접근하면 `proxy.ts`가 `jimmyflix-locale-v1` 쿠키를 먼저 확인하고, 쿠키가 없으면 브라우저의 `Accept-Language`를 사용해 해당 언어 주소로 이동한다.
- 지원 언어를 판단할 수 없으면 영어를 사용한다.
- 헤더의 `KO` 또는 `EN` 버튼은 현재 경로, 검색어, 트렌드 기간을 유지한 채 반대 언어로 전환한다. 선택은 1년 동안 쿠키에 저장된다.
- `/movies/123` 같은 기존 북마크와 외부 링크도 언어가 포함된 새 주소로 자동 연결된다.

## 번역 범위

`lib/dictionaries.ts`에 화면 문구와 접근성 이름을 모았다. 내비게이션, 검색, 목록, 트렌드, 상세 탭, 빈 상태, 오류, 재시도, 404, 로딩 상태와 메타데이터가 선택한 언어를 따른다.

TMDB 요청에는 영어 `en-US` 또는 한국어 `ko-KR`를 전달한다. 따라서 제목, 줄거리, 장르, 인물 역할, 제작 국가와 검색 결과도 가능한 범위에서 같은 언어로 표시된다. TMDB에 해당 언어 번역이 없는 필드는 TMDB가 제공하는 대체값을 사용하며, 앱 자체의 빈 상태 문구는 항상 선택 언어로 표시한다.

## 렌더링과 캐시

`app/[locale]/layout.tsx`가 `en`, `ko` 정적 파라미터를 만든다. 페이지는 쿠키를 직접 읽지 않으므로 언어별 서버 렌더링과 Next.js 데이터 캐시를 유지한다. TMDB 요청 URL의 `language` 값이 캐시 키를 분리해 한 언어의 응답이 다른 언어 화면에 섞이지 않는다.

클라이언트 JavaScript가 필요한 영역은 언어 버튼, 테마 버튼, 검색 펼침, 상세 탭, 레일 버튼처럼 상호작용이 있는 부분에 한정한다. 번역 사전 전체는 Server Component에서만 읽고 브라우저 번들로 보내지 않는다.

## 새 문구와 언어 추가

화면 문구를 추가할 때는 `Dictionary` 타입과 영어·한국어 값을 함께 추가한다. 새 언어를 지원하려면 다음 항목을 함께 갱신한다.

1. `lib/i18n.ts`의 `locales`, `tmdbLanguage`
2. `lib/dictionaries.ts`의 새 사전
3. `proxy.ts`의 브라우저 언어 협상 규칙
4. 작은 화면의 헤더 너비와 새 언어 문구 길이 검증
5. TMDB가 지원하는 언어 코드와 검색 품질 확인

검증할 때는 `/en`, `/ko`의 홈·TV·트렌드·검색·상세·404를 확인한다. 언어 전환 후 경로와 쿼리 유지, 새로고침 후 선택 유지, `<html lang>`, 메타데이터, 모바일 320px 가로 넘침, 키보드 포커스를 함께 점검한다.
